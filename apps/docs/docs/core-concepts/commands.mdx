# Commands

Commands are handler classes decorated with `@SlashCommand()`, which receives the command definition as a plain object in the shape the [Discord API](https://docs.discord.com/developers/interactions/application-commands#application-command-object) expects. Each class must implement an `execute()` method that the framework calls when the command is invoked.

## Defining a command

```ts
import { SlashCommand, DeferReply, Author } from '@nodecord/core';
import { User } from 'discord.js';

@SlashCommand({ name: 'status', description: 'Shows your status' })
export class StatusCommand {
    constructor(private readonly statusService: StatusService) {}

    @DeferReply()
    execute(@Author() user: User): string {
        return `Hello ${user.username}, bot is online`;
    }
}
```

## `@DeferReply()`

Automatically calls `interaction.deferReply()` before invoking `execute()`. Use this for commands that perform async work and may exceed Discord's 3-second acknowledgement window.

## Return values

The return value of `execute()` is forwarded to the adapter, which handles sending the response. Interceptors can transform this value before it reaches the adapter for example, converting a plain string into a Discord embed.

## Using discord.js builders

If you prefer a discord.js `SlashCommandBuilder`, call `.toJSON()` on it: the result is the same plain object. Keeping it in its own file, similar to how DTOs are handled, also helps as commands grow to include options, subcommands, or choices:

```ts title="src/status/status.definition.ts"
import { SlashCommandBuilder } from 'discord.js';

export const StatusCommandDefinition = new SlashCommandBuilder()
    .setName('status')
    .setDescription('Shows the current bot status')
    .addStringOption((option) => option.setName('type').setDescription('Status type').setRequired(false))
    .toJSON();
```

```ts title="src/status/status.command.ts"
import { SlashCommand } from '@nodecord/core';
import { StatusCommandDefinition } from './status.definition';

@SlashCommand(StatusCommandDefinition)
export class StatusCommand {
    execute(): string {
        return 'Online';
    }
}
```

This keeps the handler class focused on logic and makes the command definition easier to read and maintain on its own.

## Autocomplete (discord.js adapter)

To add autocomplete to a command option, set `autocomplete: true` on the option, then add a method decorated with `@Autocomplete('option-name')` in the handler class. The method must return an array of `{ name, value }` objects.

```ts
import { SlashCommand, Autocomplete, Focused, Option, ChatInputOption } from '@nodecord/core';
import { ApplicationCommandOptionType } from 'discord.js';

@SlashCommand({
    name: 'search',
    description: 'Search for something',
    options: [
        {
            type: ApplicationCommandOptionType.String,
            name: 'query',
            description: 'Search query',
            required: true,
            autocomplete: true,
        },
    ],
})
export class SearchCommand {
    execute(@Option('query') query: ChatInputOption | undefined): string {
        return `Results for: ${query?.value}`;
    }

    @Autocomplete('query')
    async autocompleteQuery(@Focused() input: ChatInputOption) {
        return db.search(String(input.value)).map((r) => ({ name: r.title, value: r.id }));
    }
}
```

`@Option('query')` gives you the option object, not the raw value, so the text lives in `.value`. Inside an autocomplete method, `@Focused()` is what you want for the option being typed. See [param decorators](../adapters/param-decorators.mdx) for the full set.

Multiple autocomplete options on the same command get their own methods:

```ts
@Autocomplete('query')
async autocompleteQuery(@Focused() input: ChatInputOption) { ... }

@Autocomplete('category')
async autocompleteCategory() { ... }
```

Autocomplete methods support the same param decorators as `execute()`. If no method matches the focused option, Discord receives an empty choices array.

## Registering commands

Commands are registered by adding them to the `handlers` array of a module. Slash commands are also registered with Discord's API on startup via `loadSlashCommands()`:

```ts
await client.loadSlashCommands({ token: process.env.BOT_TOKEN!, clientId: process.env.CLIENT_ID! });
```

This overwrites the application's global commands with the ones found in your modules, so a command that is no longer in a module is removed from Discord.
